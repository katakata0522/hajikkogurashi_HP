# ミニゲームの端末別UX仕様（2026-10-11）

## 目標
ゲームエンジン・ステージデータ・保存キーは共通のまま、表示領域・説明・操作導線を画面の広さと入力特性に合わせて再配置する。スマホ用とPC用のゲームを複製しない。

## 体験の優先順位
1. いま何を達成すればいいか（初回ガイド・ステージ目標）
2. 遊べる領域（Canvas。目標や通知で恒常的に遮らない）
3. 次に押すボタン（スマホでは親指で押せる大きさ、PCではキーボード／マウス）
4. 詳細情報（ヒント・ストーリー・図鑑・編集機能）。必要時に開き、戻れる

## レイアウト
- 狭いスマホ縦: 1列。HUD／ステージ目標／Canvas／操作を上下に分ける。目標とチュートリアルは Canvas 上の常設ポップアップにしない。ゲームの初回説明をプレイ前に表示し、2回目以降は任意表示とする。
- スマホ横・縦の短い画面: 高さもブレークポイントとして扱う。スクロール可能な説明・エディタ情報領域を確保。主要操作を画面内に維持。Canvas の操作を透明なヒントで覆わない。
- タブレット: Canvas を中心に必要な情報を残す。PC専用パネルは幅が許す場合のみ表示。
- PC: Canvas を主役に保ちながら、左／右の情報レールや独立したステージ解説領域を使う。ゲーム自体は同じシミュレーション・描画系を使う。
- 拡大表示／表示領域変動: コンテンツが見切れないよう高さは `100dvh` と `vh` フォールバック、必要なスクロール領域、safe-area insets を利用する。ズーム禁止のmeta設定は行わない。
- 入力: 画面幅だけでタッチ可能性を決めない。主要ボタンはタッチ操作でも押しやすい44px程度以上を設計目標とし、PCのTab／フォーカス表示も維持する。

## 先行対応
### 漢字スライサー・マージ
- 初回のプレイ前に「落とす → 合体 → お題を達成」を例付きで説明する。説明中は物理シミュレーションを停止。
- 完了した説明は同じブラウザでは初回だけ。保存領域が使えない場合でもエラーで起動失敗しない。
- 進行中は⏸の遊び方・図鑑から見直せる。
- 横幅900px以上かつ高さ600px以上のPCでは、情報レールと盤面の2列配置にする。

### LUMEN_MIRROR
- コンパクト画面はステージ目的を HUD／Canvas の間に固定表示する。タイトル／目的／ヒントを次々と重ねるトーストを廃止。
- 「説明・ヒント」から既存INFOダイアログへ進める。ヒントもダイアログ内で確認できる。
- スマホでは「光を発射」と表記し、PCの `EMIT_PHOTON` と出し分ける。ゲームの発射ロジックは共通。
- 狭い画面ではCanvas描画型のチュートリアル表示をやめ、非重畳の説明へ移す。
- 高さの小さいエディタは設定欄をスクロール可能にし、インク容量ラベルのはみ出しを軽減する。

## 端末別受け入れ試験
- スマホ縦 320×568／360×640／390×844／430×932
- スマホ横 667×375／844×390
- タブレット 768×1024／1024×768
- PC 1280×720／1440×900／1920×1080、短いウィンドウ 1280×480
- Chrome／Edge、Android実機Chrome、iOS実機Safari（可能なら）
- テスト内容: 初回開始、再訪、ステージ選択、ステージ2目標、INFO表示と復帰、光発射／リセット、タップ／ドラッグ、縦横切替、ブラウザUIの伸縮、文字拡大、メニュー／ダイアログ／セーブ継続
- 判定: 主要操作の見切れ・横スクロール・HUD/Canvas/操作の物理的重なりゼロ。解説は再確認可能。入力を妨害するポップアップなし。
- 自動テストの成功と人間による実機・視認性レビューは別に記録する。動作未確認の端末は「対応済み」としない。

## 2026-10-11 Chromium 画面監査（PR #56追補）
GitHubブランチのHTML/CSS/JSをLinuxのChromium (Playwright) のabout:blankに注入して起動し、実ゲームロジックで画面を表示・操作した。ブラウザ管理ポリシーにより localhost／公開URLへの通常遷移ができないため、HTTP配信・実機のE2Eではない。保存はブラウザ内モックを使用した。

- 対象: 漢字スライサー・マージ、LUMEN_MIRROR。320×568 / 390×844 / 667×375 / 1024×768 / 1280×480 / 1440×900 の画面サイズを使った計36状態。
- 操作: 初回説明から開始、漢字の落下・一時停止／再開、ミラーステージ1・2、鏡の描画・EMIT発射、INFO、エディタのインポートダイアログの開閉、パレット横スクロール、設定パネル縦スクロール。
- 結果: 36状態の自動DOM検査で重なりフラグ0、ページJavaScriptエラー0。編集画面のスクロールコンテナ内部にある未表示の設定やパレットボタンは「スクロールで到達できる項目」として別途操作確認した。
- 実画面の追加指摘: 320pxで漢字スライサーの一時停止画面が説明・図鑑に押されて操作ボタンの位置が分かりにくい。モーダル本文だけをスクロールし、再開／最初からのボタンを下端に固定。
- 漢字スライサーのスマホHUDはお題を独立した2段目に確保し、視線を「お題→盤面→操作」の順に整理。PCは盤面＋情報レール。キャンバスへのキーボードフォーカス表示は残しながら強い外枠を弱めた。
- LUMEN_MIRRORの短いPC画面は、ブラウザ幅ではなく**中央ゲームカラムの幅**でHUDを縮小するコンテナクエリを追加。スマホ編集画面の設定欄に「↓ スクロール」のガイドを追加。ステージ2の目標を盤面外に保持。
- ステージ目標の表示・非表示でビューポートの高さが変わった際にCanvasが旧寸法のまま残る経路を修正。ResizeObserverのブラウザ非依存回帰テストを追加。
- 確認: `node scripts/lumen-mirror-smoke-test.mjs` / `node scripts/lumen-responsive-logic-smoke-test.mjs` / `node scripts/kanji-slicer-lifecycle-smoke-test.mjs` およびJS構文チェック成功。既存全ゲームのPlaywright HTTPテスト、iOS Safari／Android実機、Xserver本番は未実施。

公開判断: 依然Draft。スクリーンショットの受け入れ評価に加えて、通常HTTP経由のブラウザ回帰と実機での初回タッチ・画面回転・Stage2操作を確認後にReady/マージ。
